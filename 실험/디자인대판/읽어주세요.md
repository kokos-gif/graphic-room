# 디자인대판 시험작 (실험 — 앱에 아직 연결하지 않음)

"게임 설명 대판 같은 디자인대판도 코드로 그릴 수 있는가"를 해 본 것이다. 앱의 메신저 흐름에는 연결돼 있지 않다.

가상 게임 "도형 셋!"(4명, 카드 40장, 같은 도형이 3개 보이면 먼저 누른다)의 규칙 설명을 장면 4개, 17초, 960×540 으로 그렸다.
실제 상품 게임의 이름·그림은 쓰지 않았다. 그림 파일은 하나도 없고 전부 코드로 그린다.

화풍은 장면을 따로 두지 않고 같은 장면에 화풍 파일만 얹는다. `--art-style codex_v3`(V3 붓터치: 바탕을 붓 자국으로), `--art-style v4`(V4 예능 그래픽: 민색 면·또렷한 선·여러 겹 테두리 제목·방사 줄무늬). 결과는 `output/실험_디자인대판_<화풍>`에 쓴다.

## 그리는 방식 — 코드로 그리는 작가

도형을 **path 글**로 적으면, 그릇이 **질감 있는 면**을 칠하고 **굵기가 변하며 살짝 떨리는 붓펜 선**으로 외곽을 긋는다.
마지막에 화면 전체에 종이 알갱이를 얹고 가장자리를 어둡게 한다. 난수는 전부 시드 고정이라 같은 시각은 언제 그려도 같은 그림이다.

```js
K.art('M0 -30 C20 -30 30 -16 30 2 …Z', { fill: '#f6cfa6', tex: 'skin', lw: 2.8, shade: 4 })   // 얼굴 한 조각
K.outline(RING, 5.5, S.blue, 30, { to: 0.6 })                                                     // 동그라미를 60%만 — 그려지는 중
```

| 도구 | 하는 일 |
|---|---|
| `K.art(path, {fill, tex, lw, shade, drop})` | 그림 한 조각: 바닥 그림자 → 질감 면 → 가장자리 그늘 → 붓펜 외곽선 |
| `K.paint(path, {…})` | 위에서 외곽선만 뺀 것(면만 칠할 때) |
| `K.tex(색, 종류)` | 색 하나를 물감·종이·천·털실·나무·살결 무늬로 |
| `K.ink(점들, 굵기, 색, 시드, {from, to})` | 붓펜 선. 일부만 그으면 "그려지는 중"이 된다 |
| `K.trace(path)` · `K.outline(path, …)` | path 글을 따라 점을 찍어 붓펜 선이 따라가게 한다 |
| `K.text(…, {tex, drop, outline})` | 글자(질감 채움, 딱딱한 그림자). 넘침 검사에 기록된다 |
| `audit()` | 화면을 보지 않고 센다 — ① 글자 넘침·겹침·안전 영역 이탈(장면마다 0.5초 간격으로 여러 시점) ② 확정 문구가 빠졌는지, 의뢰에 없는 숫자가 생겼는지 |
| 검수판(`?view=sheet`) | 여러 시각의 화면을 한 장에 모은다. 눈으로 확인할 때 한 장만 보면 된다 |

## 파일

| 파일 | 역할 | 누가 쓰나 |
|---|---|---|
| `index.html` | 캔버스와 스크립트를 부르는 껍데기 | 고정 |
| `../../mapcg/templates/brush.js` | **작가 도구** — 붓펜 선·질감 무늬·면 칠하기·종이 마감, 재질 표. 앱의 지도와 같은 파일을 쓴다 | 한 번 만들어 두고 고정 |
| `kit.js` | **그릇** — 시간, 장면 전환, 내보내기, 글자, 넘침 검사, 검수판. 그리기는 작가 도구에 맡긴다(`K` = 작가 도구 + 그릇이 더한 것) | 한 번 만들어 두고 고정 |
| `skin.js` | **디자인 기준 묶음** — 색·글꼴·그림자·안전 영역 | 프로그램마다 사람이 정함(레퍼런스를 보고) |
| `brief.js` | **확정 내용** — 의뢰에서 확정된 문구·숫자. 자동 검사가 화면에 나온 글자와 견준다 | 의뢰마다 확인 카드에서 사람이 확정(지금은 손으로 적음) |
| `scenes.js` | **장면 코드** — 이 의뢰의 그림과 움직임 | 의뢰마다 모델이 새로 씀(이번에는 이 대화의 모델이 씀) |
| `만들기.py` | 영상·검수판 내보내기(지도와 같은 `mapcg/export.py` 를 씀). 길이·fps·크기는 적어 두지 않고 페이지가 알려 주는 값을 따른다 | — |

## 실행

```
python 실험/디자인대판/만들기.py            # output/실험_디자인대판/대판_시험작.mp4
python 실험/디자인대판/만들기.py --sheet    # output/실험_디자인대판/검수판.png
python 실험/디자인대판/만들기.py --art-style codex --sheet 3.7  # output/실험_디자인대판_codex/검수판.png
```

기본 화풍은 `claude`다. `--art-style codex`로 같은 장면에 거친 마른붓 화풍을 적용한다. 두 버전을 비교하려면 양쪽에 같은 `--sheet` 시각을 준다. `--out`으로 화풍별 결과 폴더를 만들 상위 폴더를 지정할 수 있다. 생성한 폴더의 `page/index.html`을 열면 선택한 화풍으로 재생된다.

브라우저로 `index.html` 을 열면 되풀이 재생되고, `?t=3.5` 를 붙이면 그 시각의 멈춘 화면을 본다.

## 해 보고 안 것 (2026-11-19)

**1판(평평한 색, 일정한 선)**
- 처음 쓴 그대로 영상까지 한 번에 나왔다(510프레임, 약 8초).
- 고칠 곳 4군데 중 자동 검사가 잡은 것은 1군데(글자 겹침)뿐이고, 나머지 3군데는 화면을 눈으로 봐야 알 수 있었다.

**2판(붓펜 선·질감·사람 얼굴·손·종이 마감으로 다시 그림)**
- 그리기 도구를 그릇에 넣고 장면을 다시 썼다. 이번에도 처음 쓴 그대로 돌았고, 내보내기는 약 27초로 늘었다(프레임마다 그리는 양이 많아져서).
- 검수판 한 장으로 9개 시각을 한 번에 봤다. 고친 것은 2군데다 — 넓은 배경에 되풀이 무늬가 보인 것, 카드를 가져간 뒤 화면 왼쪽이 빈 것. 둘 다 자동 검사로는 안 잡힌다.
- 사람 얼굴 4명(머리 모양·표정 4종), 손, 종, 탁자, 테이프로 붙인 쪽지까지 그림 파일 없이 나왔다. 손은 1판보다 낫지만 여전히 가장 어색한 부분이다.
**3판(재질감과 디테일을 한 단계 더)**
- 그릇: 질감 무늬를 키우고(256px) 종류마다 특징을 넣었다 — 물감 알갱이와 붓 자국, 종이에 박힌 티, 나이테, 씨실·날실, 색이 따뜻한 쪽·찬 쪽으로 살짝 치우치는 얼룩.
  면마다 가장자리에 물감이 고인 자국, 왼쪽 위 빛과 오른쪽 아래 그늘을 넣고, 외곽선은 두 번 겹쳐 긋는다. 화면 전체에 물이 고르지 않게 마른 듯한 얼룩을 옅게 얹었다.
- 장면: 종(받침 옆면·금속 반짝임·둥근 빛), 카드(두께·윤기·뒷면 마름모 무늬), 얼굴(귀·눈썹·눈빛·코·머리 윤기·옷깃), 손(소매 주름·단추·마디 주름·손톱 선),
  탁자(옆면·널 이음매·테두리 그늘), 쪽지(공책 줄·접힌 모서리·테이프 결), 제목(두께 있는 글자·윤기), 띠 박음질, 꼬리표 끈.
- 처음 쓴 그대로 돌았고 자동 검사에 걸린 것이 없었다. 내보내기는 약 31초.
- 이 장면 코드는 이 세션의 모델(Claude Fable)이 썼다. **심사 때 쓰일 Liner 모델이 같은 수준으로 쓰는지는 확인하지 못했다.**

**4판(도구 정리 + 하프톤 빼기)**
- 그리기 도구가 이 실험의 960×540 화면 하나에 묶여 있어 지도가 가져다 쓸 수 없었다. 도구만 앱 쪽 `mapcg/templates/brush.js` 로 떼어 내고, 재질의 숫자는 그 파일의 재질 표(`Brush.MATERIALS`) 한 곳에 모았다.
  옮기기 전후의 프레임 4장을 한 점씩 비교해 그림이 똑같은 것을 확인한 뒤에 다음 일을 했다.
- 망점(하프톤)을 뺐다 — 다른 예능 그래픽과 비슷해 보여서. 배경 모서리의 망점은 마른 붓 자국으로, 충격 효과 안의 망점은 가운데서 뻗는 붓 자국으로 바꿨다.
- 같은 도구로 앱의 지도를 다시 그렸다(종이·물감·붓펜 재질). 지도 쪽 색·재질·굵기는 `mapcg/templates/mapskin.js` 에 있다.

**5판(기준 하나로 + 검사 강화)**
- 영상 길이가 두 군데(장면 길이의 합, 내보내기 스크립트의 "17초")에 적혀 있었다. 스크립트 쪽을 지우고, 페이지가 프레임 수·fps·크기를 먼저 알려 주면 받는 쪽이 그대로 따르게 했다.
  만든 영상은 실제로 재서 그 계획과 견준다(960×540 · 30fps · 510프레임 — 같음).
- 자동 검사는 장면 끝 무렵 한 시점만 봤다. 중간에 나왔다 사라지는 글자는 한 번도 검사받지 못했으므로, 장면마다 0.5초 간격으로 보게 했다. 늘려도 자리 문제로 걸린 것은 없었다.
- 내용 검사를 넣었다. 확정 문구 14개가 화면에 다 나왔는지, 의뢰에 없는 숫자가 화면에 생겼는지 본다.
  넣자마자 하나가 걸렸다 — 장면을 쓸 때 덧붙인 "+4장"(의뢰 문구에는 없는 숫자). 숫자 없는 말("획득!")로 바꿨다.
  모델이 쓴 장면에서 가장 걱정되는 것이 지어낸 숫자인데, 이 검사가 그것을 잡는다는 것을 한 번 확인한 셈이다.
- 이 검사가 못 보는 것: 그림이 내용과 맞는지(카드가 몇 장 그려졌는지 등), 미감, 움직임.

|---|---|

| 재질의 느낌(얼룩·알갱이·붓 자국의 세기), 새 재질 | `brush.js` 의 재질 표 한 줄 |
